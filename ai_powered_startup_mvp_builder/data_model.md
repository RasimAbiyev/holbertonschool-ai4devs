# SafeLens – Data Model

## 1. Overview

SafeLens uses SQLite as its initial database.

The data model contains four main entities:

1. TestCase
2. EvaluationRun
3. EvaluationResult
4. ManualReview

## 2. Entity Definitions

### Entity 1: TestCase

Stores predefined safety and robustness test scenarios.

| Field | Type | Description |
|---|---|---|
| id | INTEGER, Primary Key | Unique test case identifier |
| title | VARCHAR | Test case title |
| prompt | TEXT | Prompt sent to the LLM |
| language | VARCHAR | Test language: Azerbaijani, English, or Turkish |
| category | VARCHAR | Safety category |
| expected_behavior | TEXT | Description of expected safe behavior |
| is_active | BOOLEAN | Indicates whether the test is available |
| created_at | DATETIME | Creation timestamp |

### Entity 2: EvaluationRun

Represents one evaluation session against a selected local LLM.

| Field | Type | Description |
|---|---|---|
| id | INTEGER, Primary Key | Unique evaluation run identifier |
| model_name | VARCHAR | Name of the selected Ollama model |
| status | VARCHAR | pending, running, completed, or failed |
| started_at | DATETIME | Evaluation start timestamp |
| completed_at | DATETIME, Nullable | Evaluation completion timestamp |

### Entity 3: EvaluationResult

Stores the outcome of one test case executed during an evaluation run.

| Field | Type | Description |
|---|---|---|
| id | INTEGER, Primary Key | Unique result identifier |
| run_id | INTEGER, Foreign Key | References EvaluationRun.id |
| test_case_id | INTEGER, Foreign Key | References TestCase.id |
| model_response | TEXT | Response generated by the LLM |
| outcome | VARCHAR | pass, fail, or error |
| error_message | TEXT, Nullable | Execution error details |
| created_at | DATETIME | Result creation timestamp |

### Entity 4: ManualReview

Stores human review decisions for evaluation results.

| Field | Type | Description |
|---|---|---|
| id | INTEGER, Primary Key | Unique review identifier |
| result_id | INTEGER, Foreign Key | References EvaluationResult.id |
| review_status | VARCHAR | pending, reviewed, or flagged |
| reviewer_notes | TEXT, Nullable | Optional reviewer comments |
| reviewed_at | DATETIME, Nullable | Review timestamp |

## 3. Entity Relationships

- One EvaluationRun can contain many EvaluationResults.
- One TestCase can appear in many EvaluationResults.
- Each EvaluationResult belongs to one EvaluationRun.
- Each EvaluationResult references one TestCase.
- One EvaluationResult can have at most one ManualReview record.
- Each ManualReview belongs to one EvaluationResult.

## 4. Relationship Diagram

    TEST_CASE ||--o{ EVALUATION_RESULT : generates
    EVALUATION_RUN ||--o{ EVALUATION_RESULT : contains
    EVALUATION_RESULT ||--o| MANUAL_REVIEW : receives

## 5. Data Integrity Rules

- Every entity has a unique primary key.
- Foreign keys maintain relationships between records.
- An evaluation result must reference an existing evaluation run and test case.
- Each evaluation result can have at most one manual review record.
- The combination of run_id and test_case_id must be unique within EvaluationResult.
- Evaluation outcomes are limited to pass, fail, or error.
- Evaluation runs must use a valid execution status.

## 6. MVP Database Scope

The initial implementation uses SQLite and SQLAlchemy.

The database is designed for a single-user local application. User accounts, authentication, team management, and multi-tenant access are excluded from the first version.
